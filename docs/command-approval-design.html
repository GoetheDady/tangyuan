元宵 · 命令审批设计

默认免审 + 命令作用域边界 · 对应 ADR-0039，取代 ADR-0027 的"每次执行前必须审批"

参考 Codex 沙箱 + 审批分层 · Hermes 硬性拦截
1六条核心共识
免审判据 = 命令作用域边界只动当前 Agent 工作空间 + 无网络 + 非破坏性 → 默认免审；越界才审批。不是模型信心。
三层权力Agent 提议（riskLevel + 理由）→ 确定性规则裁定 → 用户覆盖（Agent 命令许可）。Agent 没有免审决定权。
三档处置normal 免审只记录；medium 审批、可记住；high 永远逐次审批、不可记住。
审批者只有人不做独立自动审查者（不引入 Codex auto-review 等价物）。
分层实现MVP 先做静态判定（扩展 assessBashRisk），后续接入 macOS Seatbelt 强制沙箱兜底。
硬性拦截清单系统级不可逆操作直接拒绝，不进审批，不可覆盖。
2一次命令执行的完整旅程
Agent 提议执行 run_command附 riskLevel 与理由（提议权）
↓
硬性拦截检查命中 → 直接拒绝，连"允许"按钮都没有
↓ 未命中
作用域边界判定（确定性规则）工作空间内 + 无网络 + 非破坏性
↓
normal · 边界内
免审直接执行仅记录执行历史
medium · 越界但可逆
弹窗审批可"记住"→ 写入 Agent 命令许可
high · 不可逆 / 破坏性
弹窗审批永远逐次确认，不可记住
↓ 用户允许
执行命令获批命令仍拥有当前 macOS 用户权限（ADR-0027 保留条款）
↓ 用户拒绝 / 取消 / 会话退出
不执行以可理解的拒绝结果返回 Agent（fail-closed）
3三档风险处置
档位含义典型命令默认处置能否"记住"
normal 边界内：只动工作空间、无网络、非破坏性 git status ls cat grep 免审直接跑，只记录历史 不需要记住
medium 越界但可逆：联网、写工作区外 git push npm install curl 弹窗审批 可以（写入 Agent 命令许可）
high 不可逆 / 破坏性操作 rm -rf（非硬性范围） 弹窗审批，规则与许可都不能覆盖 永远不可以
4硬性拦截清单（不可绕过）

拦截范围

  • rm -rf / 及变体（含 --no-preserve-root）
  • fork bomb（:(){ :|:& };: 等）
  • mkfs / 格式化、dd 写块设备（/dev/sd*、/dev/rdisk*）
  • 覆盖写入 /etc、~/.ssh 等关键系统 / 凭据路径

行为

  • 命中 = 直接拒绝执行，返回解释性错误给 Agent
  • 不进审批流程，连"允许"按钮都不出现
  • 不可被"记住"、不可被任何许可覆盖
  • 合理需求请在 Agent 之外手动执行
参考 Hermes hardline blocklist："floor below yolo"——在审批层之前触发，无覆盖开关。
5与主流 Agent 对照

Codex

  • 沙箱（macOS Seatbelt / Linux bwrap）+ 审批策略两层
  • 边界内自动跑；逃逸（写工作区外、联网）才审批
  • 静态安全白名单（只读命令集）+ 用户 allow/prompt/deny 规则
  • 可选独立审查 Agent（auto-review）——我们不做

Claude Code

  • 内置只读命令集（ls / cat / grep / 只读 git…）任何模式不弹窗
  • 权限由运行时强制，不由模型决定
  • 规则顺序：deny → ask → allow；"允许"按仓库 + 命令永久保存

Hermes

  • 危险模式黑名单，命中必审批
  • hardline blocklist：yolo 也拦不住
  • smart 模式用辅助 LLM 评估，不确定才转人工——我们不做
6实施顺序
MVP · 静态判定扩展 assessBashRisk 为完整作用域判定（安全白名单 + 危险模式 + 硬性拦截）；request() 对 normal 直接放行；更新 run_command 文案与测试。
后续 · 沙箱兜底在 run_command 执行边界接入 macOS Seatbelt 强制沙箱，静态判错的越界动作由系统拦截并转入审批。
