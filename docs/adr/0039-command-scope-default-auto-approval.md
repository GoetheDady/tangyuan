# 默认免审：命令作用域边界取代逐条审批

ADR-0027 要求每次 bash 执行前都必须创建审批请求。实践表明高频低风险命令（状态查询、只读命令、工作空间内的小操作）产生大量无意义弹窗，摩擦集中在正常开发流。"让 Agent 自己判断是否审批"的方案不可行：执行者与审查者同属一条信任链，提示注入或任务压力下模型无法可靠地自我评估，免审决定权不能交给被审查者（参考 Codex、Claude Code 的权限由运行时强制、不由模型决定的共同设计）。

## 决策

- 免审判据为**命令作用域边界**：命令仅作用于当前 Agent 工作空间内、无网络访问、非破坏性模式，三条同时满足时默认免审执行；任意一条越界即创建审批请求。
- 风险判断分三层权力：**Agent 提议**（提交 riskLevel 与理由，即命令风险判断）→ **确定性规则裁定**（内置默认高风险策略 + 用户策略）→ **用户覆盖**（Agent 命令许可）。Agent 不拥有免审决定权。
- 高风险命令维持 ADR-0027 / ADR-0038：永远逐次确认，不可加入 Agent 命令许可。
- Agent 命令许可保留为默认免审之上的用户覆盖层；用户手动收紧命令为逐次确认的通道为后续项，MVP 暂不提供。
- 配套设计说明见 `docs/command-approval-design.html`。
- 三档风险处置（映射 Codex 的静态判定分层）：
  - `normal`（安全白名单：只读命令及参数受限的安全形式，如 `git status`）→ 默认免审，仅记录执行历史；
  - `medium`（非白名单、非危险模式，如 `git push`、`npm install`）→ 默认审批，可被"记住"写入 Agent 命令许可；
  - `high`（危险模式，如强制删除）→ 永远逐次审批，不可记住，规则与许可均不能覆盖。
- 审批者只有用户本人；不引入独立自动审查者（不做 Codex auto-review 等价物）。
- 硬性拦截清单：仅覆盖"几乎不可能是正常需求"的系统级不可逆操作（`rm -rf /` 及变体、fork bomb、`mkfs`/`dd` 写块设备、覆盖写 `/etc` 与 `~/.ssh` 等关键路径）。命中即拒绝执行并返回解释性错误，不进审批流程，不可被记住或被任何许可覆盖。

## 取代

本决策取代 ADR-0027 中"每次执行前必须审批"的默认行为。ADR-0027 关于 Main 持有审批状态、展示完整命令与 `cwd`、明确获批命令仍拥有当前 macOS 用户权限、取消或退出时自动拒绝的其余决策继续有效。

## 判定机制：分层采用 Codex 模式

边界判定采用 Codex 的两层结构：声明式规则判定 + 系统级沙箱强制。命令在边界内自动执行（免审），越界动作进入审批流程，审批可交给用户或独立审查者；网络默认关闭，需要时经审批或显式开启。

落地分两步：先实现静态边界判定（扩展 `assessBashRisk` 为完整的作用域判定纯函数，可测试、零依赖），同时在 `run_command` 执行边界预留沙箱执行器接缝；后续在 macOS 上以系统 Seatbelt 实现强制沙箱兜底。MVP 阶段以静态判定为准，沙箱为长期安全底座。

## 实施顺序

1. MVP：扩展 `assessBashRisk` 为完整的作用域判定（安全白名单、危险模式、硬性拦截），`normal` 直接放行；同步更新 UI 文案与测试。
2. 后续：在 `run_command` 执行边界接入 macOS Seatbelt 强制沙箱作为兜底。
